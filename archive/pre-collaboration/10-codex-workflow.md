# Codex 协作、版本控制与 Handoff

版本 0.6 · 2026-10-27 · 已授权协作流程

## 1. 每轮工作闭环

1. 读取 AGENTS.md、工作进度和讨论路线，检查 Git 分支、工作区和远程状态。
2. 明确本轮范围及完成标准；业务待定事项先讨论，维护类授权直接执行。
3. 修改相关正文；新共识同步决策、讨论路线和进度，避免维护互相冲突的副本。
4. 检查 diff、链接和一致性；当前没有构建或运行测试，不能报告业务验证通过。
5. 更新进度，选择本次文件暂存并审查；重大变更自动 commit、push 和远程核对。
6. 回复变更结果、验证、提交短哈希、分支、推送结果及下一步或阻塞。

这里的“自动”指 Codex 在任务收尾主动执行，依赖会话实际执行指令；AGENTS.md 本身不会在后台运行。当前不安装保存即提交、定时推送或 Git hook，避免将未完成工作或失败检查推入远端。

## 2. Git 操作约定

规范远程地址为 `git@github.com:YuchenCC/astra-core.git`，默认分支 `main`。新专题需要隔离时使用 `docs/<topic>`、`feat/<topic>`、`fix/<topic>` 等分支，推送当前分支；不自动合并。小型串行文档维护可直接在 main 完成。

新机器需具备仓库访问权限并配置 Git 作者身份。SSH 不可用时可使用已经授权的 HTTPS 凭证，通过 Git URL 重写或 HTTPS remote 工作；不得把凭证写入仓库。作者身份仅在仓库本地配置，不修改全局设置。

常用核对命令：

```sh
git status --short --branch
git remote -v
git diff --check
git diff
git diff --cached
# 以下分支名以实际工作分支为准
git push -u origin main
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
git status --short --branch
```

命令行凭证缺失但 GitHub 连接器已获写权限时，可用连接器发布经过检查的文件，并 fetch 回本地核对内容和历史；必须披露发布方式和命令行 push 仍未就绪。首次空仓库发布可保留本地初始化分支，再让 main 跟踪连接器生成的远程历史。后续优先修复 Git 凭证，避免维护两套历史。

push 成功且 HEAD 与远程跟踪分支一致才称为已通过 Git 推送。远程拒绝、权限失败、检查失败分别记录，不能以一次本地 commit 代表整个闭环成功。

## 3. 交接内容

工作进度文件维护以下信息：

- 当前阶段和本轮目标；已完成内容及影响文件。
- 检查命令、结果和未验证范围。
- 尚未确认的问题、阻塞、恢复命令。
- 下一轮首个具体动作和所需阅读材料。

Git 是历史来源；进度文件呈现当前状态和简要里程碑，不复制所有 diff。讨论路线承载业务共识，工作进度承载执行交接。推送结果在会话报告；发生失败时写入进度，下次成功后清除已解决阻塞。

## 4. 中断与恢复

新会话先核对实际工作区和 git log，再读取进度。发现未提交工作先识别归属，不直接清除。已提交未推送则检查远程后补推；已推送则继续下一专题。文档与 Git 实际状态冲突时以检查结果为准，并修正文档。

遇到业务边界尚未确认，保留问题供讨论；遇到外部权限阻塞，完成所有可执行工作并保存本地提交，明确需要用户解决的最小事项。
